# Архитектура

## Пакеты

```
packages/sim      детерминированная логика: math, rng, terrain, physics, entities, weapons, turns, scheme, hash
packages/mapgen   генерация карт по seed (детерминированная)
packages/content  данные: оружие, пресеты схем, темы, Wormpot, фразы
packages/render   PixiJS: чанки земли, спрайты, камера, вода, частицы, интерполяция
packages/ai       бот: перебор выстрелов на клоне симуляции
apps/client       Vite + Preact: цикл, ввод → команды, UI, аудио
```

Зависимости направлены строго вниз: `client → render, ai → sim, mapgen, content`.
`sim` не знает про DOM, рендер, время и `Math.random`.

## Оружие: спек и набор правил

Оружие описывается одной записью `WeaponSpec` с секциями `sim` (флаги + архетип + числа), `ui` (имя,
подсказка, иконка, клетка панели), `ai` (использует ли бот, порядок, дальность) и `view` (вид, звук).
Типы - в `sim/src/weapons/spec.ts`, данные - в `content/src/weapons/*`. `sim` данных не знает:
`Ruleset` (`sim/src/weapons/ruleset.ts`) собирается из спеков в `content` (`RULESET`) и передаётся в `Game`
через `GameSetup.rules`. Глобального реестра нет, наборы правил можно держать рядом (тесты `sim` играют
своим одним оружием). Спек компилируется в `WeaponDef` (флаги + `fire`) архетипом из
`sim/src/weapons/archetypes/*` или именованным поведением из `behaviours/*`.
Бот (`ai`), панель и ввод (`client`), свет/след снаряда (`scene`) и проверка видов в `render` читают
спеки из `game.rules`, а не свои таблицы. Как добавить оружие - `docs/design/adding-a-weapon.md`.

Виды сущностей в `render`: `Map<EntityClass, ViewFactory>` в `render/src/views/index.ts`, один файл на вид
(`views/*.ts`), поиск идёт вверх по цепочке классов (наследник `Projectile` берёт вид базы). Фабрика получает
`ViewContext` (мир, `crateSpy`), который держит `GameScene`; глобального состояния нет. Снаряд рисуется по
таблице `PROJECTILE_LOOKS` (спрайт или код); процедурные тела остались только там, где арта нет. Функции цвета
(`mixColor`, `lerpColor`, `darken`) - в `render/src/color.ts`.

## Детерминизм

Одинаковые seed + схема + лог команд ⇒ побитово одинаковое состояние в любом браузере.

- Фиксированный шаг **50 Гц** (`TICK_MS = 20`). Рендер интерполирует между тиками.
- Числа: `float64`, только операции, корректно округляемые по IEEE-754 (`+ − × ÷`, `Math.sqrt`,
  `Math.floor/ceil/round/trunc/abs/min/max/sign`). Тригонометрия — через `sim/math` (таблица синусов).
  Никаких `Math.sin/cos/atan2/pow/exp/log/random`, `Date`, `performance` — запрещено ESLint.
- Случайность — xoshiro128** в состоянии мира.
- Порядок обхода — по целочисленным id; никаких итераций по объектам с недетерминированным порядком.
- Хеш состояния (FNV-1a по typed-массивам и полям сущностей) — для golden-тестов и детекции рассинхрона.

## Команды

`{ tick, kind, ... }` — единственный вход симуляции. Клавиатура/мышь/тач/бот/сеть порождают команды.
Реплей = `{ version, seed, mapParams, scheme, teams, commands[] }`.

### Пауза и реплеи

Пауза (меню Esc) живёт только в клиенте: `FixedLoop.paused` перестаёт вызывать шаг симуляции и не копит время, поэтому после продолжения нет «догоняющего» всплеска тиков. Пока игра стоит, команды не генерируются и не записываются (ввод отключён, очередь сбрасывается), а запись реплея индексируется `world.tick`, который стоит на месте. Значит журнал команд, итоговый хеш и позиция воспроизведения при паузе и без неё совпадают; пауза не нужна ни в `Command`, ни в хеше, ни в `REPLAY_VERSION`. При просмотре реплея пауза ставит на паузу и воспроизведение (то же `paused`). Настройки (`settings.ts`, `localStorage`) также вне симуляции.

Пауза — состояние UI одного клиента; для онлайн-lockstep нужна отдельная политика (по умолчанию: в lockstep-матчах паузы нет). Автопаузы по потере фокуса (blur) нет: ограничение dt до 250 мс делает возврат в окно безвредным.

## Земля

- Симуляция: `Uint8Array` W×H, `0` — воздух, `1` — земля, `2` — неразрушаемая.
- Рендер: чанки 256×256, R8-текстура маски + тематический шейдер (почва, трава сверху, кайма кратеров).
  Изменения маски помечают грязные чанки, перезаливаются только они.
