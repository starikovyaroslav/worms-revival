# Игровая постановка v1: реакции, хват и острова

Это первый рабочий проход по трём замечаниям к самому матчу. Он не закрывает
всю покадровую анимацию персонажей и не делает процедурную карту равной
нарисованному концепту.

Продолжение ведётся тремя самостоятельными блоками. Первый:
[исследование пластики и спецификация пилота](worm-motion-research.md).
Ниже — описание прежнего первого прохода, не приёмка полноценной анимации.

## 1. Реакции персонажа

Для `brutal` созданы **16 отдельных рисунков**, а не повороты одного спрайта:
четыре кадра отброса, четыре приземления, по два слабого и сильного удара,
четыре попадания в воду. Первый кадр приземления используется для подготовки
в воздухе; контакт сразу начинает расплющивание, затем отскок и восстановление.

`WormReactions` выбирает клипы по переходам состояния, изменению здоровья,
предыдущей скорости и пересечению поверхности воды. Вода запускается до того,
как симуляция окончательно объявит утопление; клип не перезапускается на смерти.
Отброс использует локальный циклический таймер, остальные клипы конечные.
Смерть прерывает незавершённую реакцию удара.

У остальных **35 доступных скинов новых рисованных reaction-листов ещё нет**.
Они сохраняют собственные `fall`/`hurt`/`land` и ограниченную деформацию тела;
не вращаются целой картинкой вокруг оси и не подменяются коммандос.
Для полноценного результата нужны собственные последовательности каждой личности,
включая характерные реакции тяжёлых, пожилых, больных и остальных типажей.

## 2. Удержание оружия

Для **всех 36 доступных скинов** созданы отдельные нейтральные корпуса без
запечённых рук и удерживаемых тростей. Они используются только при видимом
ручном вооружении; старые лица/позы прыжка, броска, верёвки, победы и т. п.
не заменяются чужими персонажами. Размер каждого корпуса привязан к прежней
высоте своей личности, а не к размеру нового PNG.

Добавлены 16 рисованных частей рук: плечо, предплечье, хват и поддерживающая
кисть для обычной кожи, чёрной кожи/перчаток, бледной и пожилой кожи.
Локоть и запястья рассчитываются отдельно; обе кисти находятся на той же
сборке, что и оружие. У базуки хват перенесён на рукояти, убран отодвигающий
её от тела `shoulderClearance`, поддерживающая кисть закрытая. Граната
использует объёмный снаряд вместо маленького инвентарного значка.

Прозрачные поля текстур больше не уменьшают оружие: `assets.tight` создаёт
GPU-видимый прямоугольник без изменения исходных пикселей. Углы сглаживаются
одинаково при разных FPS, а в момент выстрела совпадают с актуальным углом.

Важно: ось нарисованного ствола вычисляется вокруг настоящего `worm.cy`
симуляции, а не вокруг произвольного плеча. Кисти подстраиваются под эту ось;
выбор скина не меняет траекторию. Мортира остаётся отдельной наземной сборкой
с неподвижной опорой, её трубка и прицел используют ту же ось выстрела.

Это ещё **не** набор уникальных анимаций перезарядки, переноски, перехвата
и отдачи для каждой личности и каждого оружия. Корпус при удержании использует
нейтральную рисованную основу; полноценный отдельный цикл ходьбы с оружием
остаётся следующим этапом. Руки имеют четыре материала, а не точное
воспроизведение каждого костюмного рукава. Дальнейшую художественную
оценку нужно делать по крупным планам, не по числу успешно загруженных текстур.

## 3. Рельеф и вода

Новый генератор островов v2 строит 3–5 масс с разными высотами и ширинами,
затем добавляет неровности и небольшие террасы. Есть нижние арки с опорами,
боковые пещеры и переходы между островами. Деревянные настилы — настоящий
разрушаемый материал `Bridge`, а не декорация поверх пустоты. Стойки и канаты
не мешают столкновениям и исчезают на разрушенных участках настила.
Остаются открытые водные промежутки.

Вода закрывает подводную землю и объекты непрозрачной глубиной в обоих
рендерерах. Прозрачность оставлена у небольшого поверхностного гребня.
Меню также проверяет воду раньше земли и больше не рисует подводный грунт
поверх заливки воды. Физическая маска под водой сохраняется: её удаление
ради картинки было бы изменением симуляции.

Генератор v1 сохранён. Старые `MatchConfig` без `mapVersion` используют v1;
новое меню записывает `mapVersion: 2`. Превью и матч используют одну версию.
Неизвестные версии в повторах отклоняются. Старый алгоритм cavern не заменён.

Рельеф стал разнообразнее структурно, но ещё не равен концепту: нужны менее
повторяющиеся скальные поверхности, более выразительные травяные кромки,
декорации и дальнейшая настройка форм/баланса на большом наборе сидов.

## Исходники, генерация и воспроизводимость

Все новые растровые изображения получены встроенным **imagegen**, не CLI.
Мастера и точные промпты: `concepts/combat-motion-v1/`:

- `brutal-reactions.png` + `.prompt.txt`;
- `arm-parts.png` + `.prompt.txt`;
- `weapon-bodies-{1,2,3}.png` + `.prompt.txt` и соответствующие `-reference.png`;
- для всех трёх корпусов к основному промпту добавлялся текст
  `weapon-body-addendum.prompt.txt`;
- `weapon-body-jobs.json` фиксирует порядок личностей в каждом листе.

Публичный пак: `apps/client/public/assets/reactions/` — 68 записей манифеста
(16 реакций, 16 деталей рук, 36 корпусов). `npm run art:reactions` повторяет
экспорт и аудит. Экспорт сохраняет исходные RGBA-пиксели без палитры,
постеризации или уменьшения; масштаб задаётся только манифестом и рендерером.
`tools/art/weapon-body-references.mjs` воспроизводит исходные контактные листы.

## Проверки

- `npm run check`, `npm run build`, `npm run art:test`;
- `npm run test:combat-art`: побайтовая проверка 16 реакций, плотность всех
  частей и браузерная проверка 36 × 67 × 2 × 5 сочетаний;
- реальное проигрывание кадров, немедленное расплющивание, вода до смерти,
  конечное исчезновение, отсутствие вращения всего тела;
- проверка пикселей непрозрачной воды поверх контрольного слоя в обоих стилях;
- `node tools/art/skin-game-check.mjs`: составы, позы, 67 вооружений,
  запись/проигрывание повторов, legacy fallback и офлайн-превью;
- `npm run test:determinism`: Node/Chromium/Firefox/WebKit; старый матч
  и новые v2-маски четырёх сидов, плюс стартовая симуляция v2.

Автоматические проверки не являются утверждением художественной готовности.
