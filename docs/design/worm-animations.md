# Классы, персонажи и анимации — 2026-10-22

В игру подключены **15 отдельных персонажей**, по **16 рисованных поз** каждому
(240 кадров). Типаж теперь является классом команды, а не одним скином на всех.
В меню доступны выбор класса и явный выбор образа каждого участника. Образы различаются
лицами, телосложением и одеждой, а не перекрашиванием одного спрайта.

## Состав и незавершённая часть

| Класс        | Готовых персонажей |
| ------------ | -----------------: |
| Брутальные   |                  2 |
| Мягкотелые   |                  2 |
| Гламурные    |                  3 |
| Пожилые      |                  2 |
| Больные      |                  2 |
| Ветераны     |                  2 |
| Классические |                  2 |
| Доминатрикс  |                  0 |

Для команды крупнее доступного состава образы повторяются по кругу. Полного состава
уникальных червей на любую численность пока нет; дополнительные индивидуальности —
отдельное расширение арта. Назначение вручную позволяет выбирать и повторять образ.

Анимационный запрос доминатрикс отклонён встроенным генератором. Её утверждённый
концепт сохранён, но не выдан за анимацию и не подменён другим персонажем. Класс
недоступен в селекторе. Ожидается выбор владельца: неэротическая версия в закрытом
чёрном костюме либо пока только концепт. Статус записан в
`tools/art/skin-animation-status.json`; обходить отказ генератора нельзя.

## Анимационная модель

Идентичность → профиль пластики → текущая поза → независимое крепление оборудования.
Профили задают дыхание, покачивание, наклон и отдачу: тяжеловес устойчивее,
мягкотелый пружинит, пожилой сутулится, ветеран движется асимметрично.
Это только внешний вид: скорость, здоровье, баллистика и коллизии одинаковы.

Набор поз: ожидание, моргание, четыре фазы ходьбы, прыжок, падение, приземление,
получение урона, прицеливание, бросок, ближний бой, верёвка, поражение и победа.
Используются рисованные кадры и вторичная процедурная пластика, а не скелетная анимация.
Это не 67 уникальных рисованных роликов стрельбы: общие позы тела сочетаются с
отдельными спрайтами оружия и отдачей. Парашют, заморозка, невидимость и смерть
сохраняют индивидуальность; активный ранец рисует существующий JetPackView.

Для всех **67** зарегистрированных видов оружия/утилит задана роль крепления.
Ширина пистолета — 8 единиц мира, РПГ — 27, минигана — 29 независимо от скина и PNG.
Есть рука, плечо, нижняя точка установки и наземный узел; предусмотрены поправки
к конкретным персонажам. Миномёт имеет отдельные основание и поворачиваемый ствол,
не двигающиеся вместе с дыханием тела. Для налётов используется рация, для удалённых
действий — пульт, а не самолёт в руке. Брошенные/установленные объекты не дублируются
на персонаже во время действия.

## Формат и исходники

- Поставка: `apps/client/public/assets/skins/`, 17 PNG / 260 runtime-записей.
- 15 атласов персонажей по 768×768; ячейка 192×192, размер в мире 32×32 (плотность 6×).
- 16 отдельных изображений оборудования в общем `weapons.png`, ещё 4 части в `equipment.png`.
- Одна шкала и линия опоры на весь набор поз персонажа. Разделение компонентов
  сохраняет поднятые руки и отдельно стоящие костыли; обрезанная кисть classic/throw
  заменена отдельным проверенным ремонтным изображением.
- Исходные RGB и непрерывная альфа сохранены; DB32-квантизации и бинарной альфы нет.
- Атлас загружается один раз, кадры разделяют TextureSource. Отсутствующий пакет
  не ломает игру: остаётся прежний рендер червя.

Режим генерации — встроенный imagegen с концептом конкретного персонажа как референсом.
Точные запросы: `tools/art/skin-animation-prompts.mjs`,
`tools/art/skin-animation-repairs.json`, `tools/art/skin-equipment.prompt.txt`.
Полноразмерные мастера находятся локально в игнорируемом `assets-in/skins/`;
для запуска/production-сборки нужны только поставляемые публичные атласы.
Полный арт игры после дополнения: **715 PNG / 956 уникальных runtime-id**.

```sh
npm run art:skins
npm run art:audit
npm run art:test
node tools/art/skin-game-check.mjs http://127.0.0.1:5174/
```

Старое поле `skin` в конфигурациях сохранено. Новые поля `characterClass` и
`characterVariants` не попадают в GameSetup и хеш симуляции. Запись повтора фиксирует
разрешённый состав по участникам, чтобы пополнение класса не меняло лица старого матча.
