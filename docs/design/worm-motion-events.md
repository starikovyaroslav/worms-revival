# Блок 1, этап 1: события движения и часы персонажей

Реализовано 2026-10-23. Это техническая основа пилота из
[исследования пластики](worm-motion-research.md), не поставка новых рисованных клипов.
Оружие визуально, генератор карт и графические ассеты не менялись.

## Что работает иначе в матче

- Отброс начинается по событию импульса. Второй взрыв или удар в полёте даёт
  новый старт без необходимости сначала перейти из `airborne` в idle.
- Каждый физический контакт передаёт нормаль, входящие `vx/vy` **до** отражения
  или обнуления и состояние после отклика. Это работает и при нескольких тиках
  между двумя кадрами рендера. Поверхность определяется нормалью, не потерей HP.
- При первом пересечении воды ногами выдаётся событие поверхности до окончательного
  утопления. Позднее терминальное уведомление не перезапускает клип, даже если он
  уже закончился. Координаты события — позиция тела / уровень воды, не точная
  субтиковая точка пересечения траектории.
  Пересечение проверяется после всех движителей тика, включая верёвку/ранец;
  при мгновенном глубоком погружении входящая скорость сохраняется до её обнуления.
- Урон без механического импульса/контакта больше не запускает `hit-light/heavy`
  у скинов. Убрана и запоздалая дополнительная реакция из соседних снимков здоровья.
- Убрана поза подготовки к расплющиванию, которая включалась в любой точке длинного
  падения при `vy > 3`. Новая подготовка около земли пока не нарисована и не реализована.
- Время реакций, действий, дыхания и исчезновения `SkinActor` привязано к
  `(world.tick - 1 + alpha) / TPS` с ограничением снизу нулём — тому же интервалу,
  в котором интерполируется положение тела. Пауза сохраняет фазу, slow motion и
  ускоренный повтор изменяют её вместе с физикой. Запоздавший рендер не начинает
  давно закончившийся контакт с первого рисунка.

Событие `worm-motion` содержит тик и монотонный косметический `sequence`.
Порядок сохраняется независимо от частоты `drainEvents`; повторная доставка
события не перезапускает анимацию. `impulse.vx/vy` — результирующая скорость
после запуска, `contact.vx/vy` — скорость до отклика о поверхность.
Счётчик событий не входит в хеш. Он не читается физикой или правилами;
не добавлены команды, случайность, поля реплея или новые физические состояния.

`World` передаётся в места физического толчка существующих видов оружия только
для выдачи уведомления; числа урона, импульса и порядок физических операций сохранены.
Вне матча инструменты просмотра по-прежнему могут передавать относительный `dt`.

## Что остаётся временным

- Используется прежний набор: 4 рисунка полёта, 3 уникальных контактных рисунка
  жёсткой посадки, по 2 рисунка flinch, 4 воды — только у `brutal`.
  У остальных сохраняются собственные базовые позы и ограниченная деформация.
- Для стены/потолка пока выбирается существующая реакция удара, **не** напольное
  расплющивание. Отдельные ключевые позы, ориентация по нормали и актёрские переходы
  — следующая поставка пилота.
- Слабое приземление не получает новый клип; паузы, фазы восстановления и разница
  типажей ещё требуют художественной работы. Пороги 2/3/6 px/tick — настройки
  нашего временного выбора клипов, не измерения World Party или Armageddon.
- Эффекты окружения, старый legacy-рендер без скинов, звуки и hit-stop не переведены
  на этот контроллер. Это не заявление о синхронизации вообще всей презентации игры.
- Рисованный водный клип по-прежнему использует прежнее визуальное погружение;
  полноценная маска тела и разные направления входа остаются в художественном пилоте.

## Проверки

- `npm run check`: типы, ESLint и 371 тест.
- `npm run build`: production-сборка; остаётся предупреждение о размере основного чанка.
- `npm run test:determinism`: одинаковые хеши Node, Chrome, Firefox, WebKit;
  финальный контрольный хеш `114089616`.
- Новый `packages/sim/test/wormMotion.test.ts`: настоящий контакт с полом, стеной,
  потолком; повторные импульсы/отскоки без рендера; раннее пересечение воды;
  отсутствие контакта от изменения HP. Отключение выдачи событий сохраняет
  одинаковые хеши на каждом из 180 тиков сценария.
  Также проверены внешний движитель после шага червя и мгновенное глубокое погружение.
- `combatPresentation.test.ts`: повторные события, вход в воду и позднее утопление,
  истёкший контакт при пропущенном рендере; одинаковая фаза 30/60/144 FPS,
  скорости 0,25×/1×/2× и пауза.
- `apps/client/test/loop.test.ts`: те же комбинации через настоящий `FixedLoop`
  с управляемыми часами и общую функцию времени, используемую сценой.
- Браузерная проверка `combat-presentation-check.mjs`: 24 120 сочетаний хвата,
  проигрывание имеющихся кадров по событиям и абсолютному времени; намеренно
  неверный реальный `dt` не сдвигает фазу. Это техническая проверка, не художественная приёмка.
- Дополнительно в настоящей сцене проверена цепочка `Worm.push → World → GameScene → SkinActor`:
  продвижение фазы, повторный импульс в воздухе и многократный рендер на паузе
  без изменения фазы и хеша физического состояния.

Для нового прогона без перезаписи исторических скриншотов:
`node tools/art/combat-presentation-check.mjs http://127.0.0.1:5174/ assets-in/research/worm-motion/runtime-event-check`.

Далее — animatic реакций `brutal`, затем контрастный мягкотелый пилот,
каждый самостоятельным коммитом. Исследование оригинальных PC-версий серии
не объявляется завершённым этим техническим этапом.
