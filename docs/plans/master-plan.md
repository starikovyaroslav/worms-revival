## Порядок милестоунов и почему именно так

Сквозное правило: фундамент -> блокирующие дефекты -> расширяемость -> внешний вид -> контент. Причина: каждый следующий слой дороже переделывать, если нижний нестабилен. Масштаб экрана меняет все размеры, поэтому визуал и HUD до него — выбросить в мусор. Регистр оружия до визуальных проходов по сущностям, иначе правим 61 вид дважды. Хеш и версия реплея до любого изменения правил, иначе изменения невозможно проверить на идентичность.

- U3 (границы камеры) можно взять в M2 только после V1; если V1 затянется, в M2 делается только сброс `userScrolled` и кнопка центрирования.
- T9 (атлас) можно перенести в M3, если загрузка мешает разработке.
- Меню-сцена (V8) нельзя раньше M5: у неё нет фона.

## Чек-лист ворот качества (каждый милестоун)

Милестоун не закрывается, пока не выполнено ВСЁ:

1. `npm run check` зелёный (typecheck, lint, tests) — ссылка на прогон CI.
2. `npm run build` зелёный; размер главного чанка и число запросов ассетов записаны (база: 471 кБ / 146 кБ gzip; 321 PNG).
3. Детерминизм: `npm run test:determinism` (Node/Chromium/Firefox/WebKit) зелёный; золотой реплей проходит. Если менялась логика симуляции — `REPLAY_VERSION` поднят и записан в журнал решений; если не менялась — хеши сценариев идентичны до/после (приложены).
4. Скриншоты, свежие, на 1280x720, 1920x1080 и 2560x1440: меню, бой (сцена + HUD), панель оружия, экран победы. Для визуальных милестоунов — также 1024x768. Скриншоты сохранены в PR или `docs/plans/evidence/<M>/`. Без картинок «готово» не принимается.
5. Консоль браузера чиста: нет ошибок, нет новых предупреждений (известные PixiJS-предупреждения `fill(color,alpha)` и BindGroup на ресайзе должны быть устранены к M1/M3).
6. Проход QA: сценарий «меню -> матч vs CPU -> конец матча» руками и клавиатурой; список найденных дефектов с серьёзностью; блокеров и major нет.
7. Проход ревьюера: чтение диффа, граница пакетов, отсутствие мёртвого кода, новых строковых id, дублей; замечания закрыты.
8. Реальное железо: хотя бы один замер FPS/времени кадра на машине владельца или явная запись «не измерено».
9. ROADMAP.md обновлён в том же коммите (статусы, счётчики, найденная работа); отчёт продюсера на русском: сделано (проверено), не проверено/упрощено, заблокировано, рекомендация, риски.
10. Лицензии: каждый новый внешний файл занесён в `docs/ATTRIBUTIONS.md` (автор, URL, лицензия, дата).
