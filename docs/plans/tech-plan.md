## T1. CI-ворота `[S]`

**Цель:** ни один деплой и ни один merge не проходит без зелёных проверок.
**Файлы:** `.github/workflows/pages.yml`, новый `.github/workflows/ci.yml`, `.github/workflows/nightly.yml`.
**Результат:**

- `pages.yml`: шаг `npm run check` перед `npm run build`.
- `ci.yml` на pull_request и push: `npm ci`, `npm run check`, `npm run build`.
- `nightly.yml` (cron): `npm run test:determinism` (Node/Chromium/Firefox/WebKit).
- Кэш npm, `concurrency` по ветке.
  **Зависимости:** нет.
  **Проверка:** намеренно сломанный тест в тестовой ветке красит CI; ссылка на зелёный прогон в отчёте.
  **Definition of done:** на `main` невозможно задеплоить красный коммит; ночной прогон детерминизма отработал хотя бы раз зелёным; описано в README/ROADMAP в разделе «Как продолжить».

## T2. Целостность хеша и реплеев `[M]`

**Цель:** хеш состояния покрывает всё, что влияет на исход; старый реплей не проигрывается молча неверно.
**Файлы:** `packages/sim/src/game.ts` (`hashInto`), `worm.ts`, `world.ts`, `physBody`, `arrow`/`gravestone`/`gas`, `projectile`; `packages/content/src/replay.ts`; `apps/client/src/match.ts` (показ ошибки); новые тесты в `packages/sim/test`.
**Результат:**

1. В хеш добавлены: боезапас по командам, `shotsLeft`, `fuseSeconds`, `bounceHigh`, `target`, `suddenDeath`, `winner`, `surrendered`, `nextWorm`, `turnsTaken`, `dyingQueue`, `firedThisTurn`, `settleTicks`, `turnStartDamage`; у червяка `crateSpy`, `drowned`, `airTicks`; физика мира; `gravityScale`/`windFactor` тела; необработанное состояние Arrow/Gravestone/Gas; `spec.blast`/`owner` снаряда.
2. Тест полноты хеша: для каждого сущностного класса меняем каждое поле (через рефлексию по списку полей или явный реестр) и проверяем, что хеш меняется; поле, намеренно не хешируемое, перечислено в allowlist с причиной.
3. «Золотой» реплей: файл реплея в репозитории + ожидаемый хеш; тест падает, если логика изменилась, а `REPLAY_VERSION` не поднят.
4. `REPLAY_VERSION = 2`; реплей несёт `rulesetHash` (хеш таблиц оружия и схем).
5. Несовпадение версии/хеша: видимая ошибка в UI (не `console.warn`), реплей не стартует молча.
   **Зависимости:** T1.
   **Примечание:** любое изменение симуляции из UX-пакетов (U1, U2: оружие по умолчанию, время ящика, hot-seat) также меняет исход. Поэтому T2 идёт ДО них, а `REPLAY_VERSION` поднимается ровно один раз на милестоун, не на каждый коммит (см. master-plan).
   **Проверка:** `npm run check`, `npm run test:determinism`; тест полноты хеша красный на искусственно «забытом» поле (показать в PR).
   **Definition of done:** хеш полон по allowlist; золотой реплей в CI; версия 2; открытие реплея v1 даёт читаемое сообщение; qa подтвердил руками на одном старом и одном новом `.wrr`.

## T5. Реестр оружия и данные в `content` `[L]`

**Цель:** новое оружие = одна запись данных (+ редкий код архетипа), а не правка 8-12 файлов; числа живут в `content`.
**Сегодня:** оружие трогает sim-определение (row/col, числа inline), класс сущности, `WEAPON_INFO`, 7 схем, `ARSENAL`/`REACH` бота, `entityViews.ts` (switch, `PROJECTILE_ART`, `SPIN_ART`, instanceof), `scene.ts` (свет/следы), `sounds.ts` (строковые id), ассеты, тесты.
**Файлы:** `packages/sim/src/weapons/*`, `packages/content/src/weapons/*` (новый), `schemes.ts`, `packages/ai/src/bot.ts`, `packages/render/src/entityViews.ts`, `apps/client/src/scene.ts`, `apps/client/src/audio/sounds.ts`.
**Результат:**

1. `WeaponSpec` на каждое оружие: `{ id, archetype, params, ui: {name, hint, icon, row, col}, ai: {useInArsenal, reach}, view: {look, light, trail, sound} }`.
2. Малый набор архетипов в sim: launcher, thrown, strike, hitscan, melee, summon, tool (уточняет tech-lead по факту инвентаризации 61 вида; цель — не больше ~10).
3. Все числа баланса (~330 строк) уезжают в `content`; sim получает набор правил (`Ruleset`) через конструктор `Game`, глобальный реестр с побочными эффектами импорта удаляется.
4. `look`, id звуков, id света/следа — типизированные литералы, а не строки.
5. Тест согласованности: у каждого `WeaponSpec` есть иконка, имя, вид, звук, запись для бота (или явное «бот не использует»), место в панели без коллизий row/col.
6. Миграция по группам (guns, artillery, strikes, animals, ...) с проверкой «хеш существующих сценариев идентичен до и после» на каждой группе.
   **Зависимости:** T2, T4. Блокирует: любое новое оружие (заморозка контента, см. master-plan).
   **Проверка:** тест согласованности; сравнение хешей по 7 схемам x 3 seed до/после; `git diff --stat` для добавления фиктивного оружия-пробника показывает ≤ 2 файла (пробник затем удаляется).
   **Definition of done:** добавление тестового оружия тремя правками (спек, иконка, строка в схеме); sim не содержит русских строк и row/col; глобальный реестр удалён; tech-lead и reviewer приняли.

**Цель:** добавление сущности не требует правки `instanceof`-цепочки; убрать мёртвый код.
**Файлы:** `packages/render/src/entityViews.ts` (814 строк, разбить по файлам), `effects/*`, `color.ts`, `apps/client/src/scene.ts`.
**Результат:** `Map<EntityClass, ViewFactory>`; сопоставление «сущность -> свет/след» лежит в view-определениях, а не в `GameScene`; ~27 процедурных `new Graphics()` заменены спрайтами там, где спрайт есть; удалены `glow: () => {}`, `EffectsSystem.setRecipes` (если не используются), глобальное состояние `crateSpy` (уходит в контекст view); `mixColor/mixToward/lerpColor/darken` собраны в `color.ts`.
**Зависимости:** T5 (общая схема `view` в спеке).
**Проверка:** скриншоты 1280x720 до/после по сценарию «бой ботов, seed=1» визуально идентичны (попиксельный diff для нетронутых сущностей); `entityViews.ts` < 300 строк.
**Definition of done:** нет `instanceof`-цепочки в отрисовке; нет дублей функций цвета; qa подтвердил визуальную идентичность.
